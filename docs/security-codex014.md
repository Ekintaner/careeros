# CODEX-014 security and reliability review

Review date: 2026-10-17. Baseline: `dbe24c7597c8fd5721b9f5e3157e79825e43822b`. This is a source, dependency and regression-test review of the local application, not a penetration-test certification. No production deployment was made. No existing records were deleted, no migration was added, and AI remains disabled by default.

## Boundaries checked

- **Authentication:** issuer/audience/signature/algorithm/lifetime validation; server-side security-stamp and live-family checks; HttpOnly and SameSite cookies, Secure host cookies in Production; hashed refresh/reset secrets, absolute refresh expiry, rotation/replay revocation, user-row serialization and password-change/reset revocation. Existing real PostgreSQL tests exercise these boundaries, including concurrent refresh and host restart.
- **Authorization/IDOR:** product services use OwnedData on reads and writes; raw analytics SQL includes owner predicates and same-owner joins. Composite foreign keys prohibit cross-owner relationships. Existing two-user tests cover profiles, jobs, applications, notes, documents, resumes, matching, skills intelligence, planning, analytics, assistance and dashboard. Anonymous and foreign IDs do not become inference or document requests.
- **CSRF:** mutations require both the exact configured Origin and the custom header, independently of cookie SameSite. Real HTTP checks through Next's same-origin rewrite confirm an attacker Origin is rejected even with the custom header. Proxy does not run for API routes.
- **Uploads:** raw PDF body, 5 MiB server/stream bound, MIME/name/signature/EOF checks, server-generated storage keys, external private root, no static serving, attachment download, link checks and document lifecycle locking. New unit test accepts the exact limit and verifies cancellation. Existing tests cover invalid files, ownership, deletion restrictions and concurrency. This is signature validation, not malware scanning or full PDF validation.
- **Local AI:** still off by default; no paid/cloud fallback or model download. Explicit consent, owned saved context, fixed loopback transport without proxies/redirects, cloud-disabled/model preflight, bounded prompt/output, cancellation, single inference gate and no held database transaction during generation. Structured output accepts grounded excerpts and allowlisted actions, not arbitrary asserted career facts; rendered output remains React text. Protocol tests use controlled providers, not a real installed model.
- **Validation/concurrency:** domain length/enumeration/URL/UTC checks, unknown DTO field rejection, request body limits, xmin conflict responses, append-only status history, transactions and restrictive foreign keys. New overlapping 100-skill batch test uses two owners in reverse order and SQL-shaped text; it verifies canonical deduplication, independent requirement levels, no invented evidence and intact tables. Existing rollback tests still pass.
- **Backups:** the documented backup procedure requires a quiescent paired database dump plus private storage. New integration drill executes real pg_dump/pg_restore on the disposable PostgreSQL container, restores private bytes into another root after the original test root has gone, checks SHA-256, reauthenticates and verifies owner download/other-owner denial and schema compatibility. It does not establish that the user's operational backups or OS ACL restoration have been tested.

## Residual risks and operational limits

1. Full npm audit still reports a high-severity `braces` advisory through ESLint's development-only dependency chain (five reported packages, one underlying advisory). No patched version is offered by the registry audit. The suggested forced downgrade of eslint-config-next to 14.x was not applied. Do not lint untrusted glob patterns; production-only audit is clean. See [advisory](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm). CI now gates production dependencies at high severity; this development-tool finding remains visible here.
2. .NET 8's documented support end is approaching (see README's Microsoft support-policy link). A framework-major migration was not folded into this hardening change. NuGet's configured advisory sources report no vulnerable direct/transitive packages at review time.
3. Production ingress, HTTPS, AllowedHosts, trusted proxy addresses, dedicated OS identity/storage ACLs and recovery delivery remain operator responsibilities. Current local preview is not a production deployment configuration. In-memory IP rate limits are per process, not a distributed abuse-control service.
4. PDF attachments may contain dangerous content; no antivirus/parser/sandbox is introduced. An untrusted process with local write permission can race filesystem link checks. There is a per-upload bound but no cumulative per-user disk quota. Monitor free disk space and protect the storage root.
5. Refresh/reset history retention is manual; revocation loads matching active rows. Profile skill lists are not paginated, although matching input sets are capped at 100 and AI context rejects more than 100 skills. These owner-local growth paths should be bounded/retained with an explicit product policy before multi-user public hosting. No destructive cleanup or silent truncation was added.
6. Dashboard/analytics/skills intelligence use database aggregates, bounded results and fixed query counts, but their aggregate work still grows with owner data. Offset pagination and substring searches can scan many rows. No speculative cache, index migration or query rewrite was added based on small local timings.
7. CSP restricts framing, object and base URLs; it is not a full nonce-based script policy. Plain-text rendering and URL validation reduce current injection exposure but do not replace a complete deployment CSP review.
8. Prompt injection can influence which source excerpts a local model selects. Grounding prevents unsupported claims but does not prove relevance or truth of saved source text. A local administrator/Ollama daemon remains trusted. No real model quality, speed, cloud-disabled daemon behavior or hardware fit was verified.
9. Keyboard, accessibility-tree and semantic-description checks are not a full spoken screen-reader or WCAG audit. Physical mobile devices and assistive technologies were not verified. See verification scope for responsive limitations.

No mandatory service, paid dependency, telemetry, data export, model installation, production migration or automatic record cleanup was added. Stop after CODEX-014; commit/push require the user's explicit approval.
